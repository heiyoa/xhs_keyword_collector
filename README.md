# 小红书聚光关键词规划采集模块

英文目录名：`xhs_keyword_collector`

## 概述

`xhs_keyword_collector` 是一个面向关键词规划场景的采集模块，用于在已登录的小红书聚光后台中，自动读取关键词规划结果并输出结构化数据。

项目的重点不在于页面抓取本身，而在于将“已登录环境复用、任务批次配置、数据采集、结果落盘”整理为一条可重复执行的链路。

## 场景示例

以一组关键词 `ai`、`ai教程`、`剪映海外版` 为例，系统需要完成以下处理：

1. 读取关键词任务批次
2. 复用当前已登录的聚光后台环境
3. 逐词触发关键词规划查询
4. 提取搜索指数、竞争度、出价等字段
5. 统一输出为 JSON 和 CSV

这类结果可直接用于投放前的关键词筛选和初步分析。

## 设计目标

- 避免关键词逐条手工查询
- 避免人工抄录导致的字段错漏
- 支持批次化执行与结果复用
- 尽量复用已登录环境，减少重复登录带来的不稳定因素

## 模块划分

### `src/browser_modules/cli/xhs-juguang-keyword-cli.js`
负责命令行入口，接收任务参数并触发采集流程。

### `src/browser_modules/sites/xhs-juguang-keyword-service.js`
负责核心采集逻辑，包括浏览器接管、关键词输入、结果字段提取与结构化落盘。

### `config/keyword_rounds/`
负责任务批次定义，用于管理不同轮次的关键词集合。

### `docs/xhs-juguang-keyword-volume-runbook.md`
负责记录执行方式、输出结构和运行约束。

## 工作流实现

项目的工作流实现如下：

1. CLI 读取关键词批次配置
2. 系统通过 binding 获取可用的已登录环境
3. 采集模块接管当前聚光页面
4. 按关键词顺序逐个发起查询
5. 解析页面返回字段并整理结果
6. 输出 JSON / CSV 结果文件

这种实现方式将“浏览器基础设施”和“业务采集逻辑”拆开，便于后续扩展更多字段或更大词池。

## 容灾与稳定性设计

### 1. 已登录环境复用
通过复用当前登录状态，减少重复登录对稳定性的影响。

### 2. binding 管理
账号、窗口、凭据和浏览器资源通过 binding 组织，降低手工参数传递风险。

### 3. 结果统一落盘
即使实时链路异常，历史结果文件仍可保留，便于补采和复核。

### 4. runbook 固化执行方式
通过运行说明固化命令格式、输入结构和输出路径，减少重复执行中的人为误差。

## 当前状态

当前版本已具备：

- 历史采集结果样例

- 核心采集代码结构

本次实时重跑仍受外部浏览器环境与页面接口影响，但该模块已足以证明关键词规划采集链路具备实现基础。
